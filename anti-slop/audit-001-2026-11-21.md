# Antislop audit 001

Date: 2026-11-21
Mode: AFTER
Scope: Pass B onboarding/PMS redesign and the current working tree.

## Findings

1. **HIGH — R-02: Em dashes appear in user-facing text and placeholder values.**
   - Evidence: `src/app/settings.tsx:278`, `src/components/onboarding/pms-step.tsx:26`, `src/components/onboarding/reminders-step.tsx:14`, and placeholder uses such as `src/app/(tabs)/maintenance.tsx:440`, `src/components/dashboard/telemetry-tiles.tsx:46`, `src/components/fuel/fuel-hero-card.tsx:81`.
   - Reason: R-02 is a Hard Gate and forbids em dashes in agent-written UI text, including placeholder glyphs.
   - Fix direction: replace prose dashes with commas/colons and use `N/A` or an empty state instead of `—`.

2. **MEDIUM — R-27: Maintenance screen does not expose a complete error state for every data source.**
   - Evidence: `src/app/(tabs)/maintenance.tsx` returns a full error view only for `maintenance.status === 'error'`; `pms.error` is rendered as plain text without retry, and `preferences.status === 'error'` falls through to default preferences.
   - Reason: R-27 requires empty, loading, and error states for every data-driven UI.
   - Fix direction: add a shared error/retry block for PMS, preferences, and document load failures.

No other HIGH findings were identified in the reviewed UI code. Awaiting approval of specific finding numbers before making any antislop-driven UI changes.
